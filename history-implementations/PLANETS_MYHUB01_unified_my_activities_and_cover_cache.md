# PLANETS MYHUB01 — Unified “Le mie attività” with status filters and fast owner covers

## Outcome and sequence

**Run after DRAFTFIX01's verified fix is merged**, against the then-current `origin/main`. Replace the existing draft-only hub and redundant management overflow with **one coherent personal management destination** showing owned Projects/Proposals, Tavoli, and Scambio/Dona listings across drafts, published/active and terminal states. Keep delegated/co-organized Projects available with truthful role and recency semantics. Reuse and enhance the existing cover-image cache so reopening a personal list does not unnecessarily redownload unchanged private covers.

## Verified implementation baseline (2026-10-21)

- `apps/mobile/lib/features/drafts/` owns the `/drafts?types=project,table,donate,exchange` page, current four type `FilterChip`s (OR combination), and an adapter over the three owner controllers. It deliberately **filters to `draft`** and sorts by true `updatedAt`; an app-bar overflow links to `/proposals/mine`, `/tavoli/mine`, and `/resources/mine` for published/history.
- The three existing `Own...` models expose actual `updatedAt`, lifecycle, title, cover path and canonical item ID. They already include draft, published and terminal records; do **not** invent a new all-content backend feed without evidence it is needed.
- `OwnProposalsScreen` and `OwnRecurringActivitiesScreen` also display delegated/co-organized work from `delegatedProjectsProvider`. `DelegatedProject` currently exposes `delegatedAt`, **not** a true content-update timestamp. Do not mislabel `delegatedAt` as Last edited.
- `apps/mobile/lib/features/cover_media/application/cover_image_loader.dart` has an app-lifetime `publicCoverBytesProvider` keyed by immutable path and an **`autoDispose` ownerCoverBytesProvider** keyed by `(ownerProfileId, objectPath)`. `CoverImage` renders placeholders while bytes load. Do not introduce a second unbounded cache or persist unencrypted private draft covers across accounts.
- Existing `/drafts` and management routes and tutorial/deep-link affordances are owned by `app/router/app_router.dart`, discovery toolbar actions, and startup tutorial. Fetch latest `main` before changes and inspect tests/docs; these paths are evidence, not a frozen implementation layout.

## Agreed product behavior

1. **One page:** Replace “Le mie bozze” with **“Le mie attività”** (EN: “My activities”, or an equivalently concise localization) as the ordinary folder/management destination. The user should not have to open separate “Miei Tavoli”/“Mie proposte”/“Miei annunci” pages just to see published versus draft records. Do not remove any lifecycle-management functionality or valid old route without an equivalent accessible path; preserve deep-link compatibility.
2. **Type multi-select:** Projects, Tavoli, Dona, Scambia. Existing contextual entry points from Projects, Tavoli and Scambio may preselect their relevant type(s). A blank selection means all, consistent with the existing draft hub. Type filters are OR within this group.
3. **Status multi-select:** At minimum Draft, Published/ongoing, Terminal/archived; keep distinct exact lifecycle labels on cards: Proposal Draft / Published (and Idea versus Defined when relevant) / Cancelled / Completed derived state; Tavolo Draft / Published / Paused / Ended; Resource Draft / Published / Closed. A published record is not automatically an ongoing event; use canonical lifecycle and derived status rather than guesses based only on date. Status selections are OR within this group, ANDed with type selections; no selected status means all. Keep filters accessible and not excessively tall at 320dp/2x.
4. **Ordering:** Default recent-first based on **actual last modification** (`updatedAt`) for owned records, including drafts and published. Stable tie-break by item kind and ID, no duplicates. Cards show type and a compact visible status tag in the upper-right or equivalently unambiguous position, plus a truthful last-edited time. Do not use publication time, upcoming occurrence time, or screen-entered time as a substitute for `updatedAt`.
5. **Delegated/co-organized:** Include current-role Project/Tavolo relationships formerly available in “My Proposals / My Tavoli.” Show a clear Creator/Co-creator/Co-organizer role where appropriate. Because the existing delegated projection has `delegatedAt` rather than `updatedAt`, either keep delegated work in a **clearly labelled separate section** ordered by delegation date, or reuse an already existing authorized genuine update timestamp if verified. Never claim it is sorted by Last edited when it is not. Do not grant editor/owner actions a delegate does not possess. Avoid duplicates if actor has overlapping owner/delegate records.
6. **Navigation and actions:** Draft tap resumes its guarded editor and preserves the existing DRAFT01 lost-response recovery behavior; published Project/Tavolo taps open canonical detail/manage destinations with existing relevant actions; terminal state remains read-only where previously required; Resource listings retain established owner management/loan/exchange controls. Preserve exact auth guard, co-organizer permissions, and author/context return behavior. After edit/publication/close, show updated row/status/sort and retain sensible filters/scroll state. No actions masquerade as success after an RPC failure.
7. **Failure independence:** A failed Projects/Tavoli/Resources owner feed must not hide successful peers or produce a generic all-page Error. Show a compact source-specific error with Retry; keep last valid same-actor rows safely visible with accurate stale/refresh UI, never leak previous account data. An empty matching set should be a genuine empty state, not a transport failure. Follow DRAFTFIX01's established diagnostics and fix, do not paper over remaining bugs.
8. **Covers:** The item title, type and status must render immediately; cover downloads must not gate the list. Reuse immutable path cache for public images. For owner-only drafts, add **bounded per-session, identity-scoped in-memory reuse** of validated image bytes or an equivalent simple safe solution. Confirm permission before first load, reject cross-actor reuse, and clear owner bytes on sign-out/account change, revoked authorization and memory pressure. Bound cache count/bytes and avoid unbounded page-wide prefetch; prefer current viewport and at most a few upcoming cards if measurements justify it. A replaced immutable path gets fresh content. Failed loads remain visibly retryable, not cached forever as success. Disk persistence of private owner media is out of scope without security review; first network load cannot be guaranteed instant.
