## Delivered UI and ownership

Ready signed-in profiles get a Settings account row, PLANETS notices / Avvisi di PLANETS, opening protected `/settings/notices`. Back returns to Settings; no primary tab or submitted-report conflation. All four consequence types have distinct active/removed episodes, localized device-time dates, verbatim selectable apply/remove reasons, and optional safe owned-content kind/title. No title links go to intentionally denied public content routes.

The feature follows the existing moderation gateway/domain/Riverpod/presentation boundaries. Lazy rows wrap on narrow screens without fixed heights; explicit text states distinguish loading, genuine empty, malformed/transport denial, first-load failure, later-page failure, retry, refresh and end of history. Page errors retain loaded rows. Refresh drops old rows before requesting page one instead of displaying old active state as freshly confirmed. Multiple episodes are not a score or global restriction summary.

EN/IT synthetic widget previews and the dedicated SDK integration harness were added using the Flutter preview/testing skills. `integration_test` is a development-only Flutter SDK dependency; its six newly resolved SDK/transitive packages are in the lockfile. Existing dependency versions were not upgraded. No production Driver extension or fixture controls were added.

## Contract and privacy evidence

- Repository migration source and generated public contract were inspected. The RPC accepts expected profile ID, limit (default 20, range 1–50) and both nullable cursor components; it orders descending `(applied_at, consequence_id)`. No SQL migration or authorization change is made.
- The app requests exactly 20 rows and carries the original timestamp string (including microseconds/timezone) and UUID into the next request, separate from localized date display. Strict parsing rejects missing/extra fields, unknown types/kinds, invalid dates/IDs, inconsistent active/removal state, oversized reasons and duplicate/non-advancing pages. A failure never becomes successful empty history.
- Exactly ten fields are accepted: consequence ID/type, active state, applied timestamp/reason, revoked timestamp/reason, content kind/ID/title. No case/audit metadata, staff actor/note, reporter identity, evidence, corroboration or counterstatement text is projected or retained.
- The controller accepts no UI-supplied identity: it derives the verified ready account, invalidates each session/request revision, clears on sign-out/switch/suspension/status failure/disposal and rejects late successes/errors, including A → signed out → A. Reasons are memory-only; no preferences/generic cache, logging, analytics, breadcrumbs or outbox delivery is added.
- `PT403` clears history and asks the existing Auth controller to refresh its narrow own-suspension status. The existing router/status screen owns denial, Check status again and Sign out. General history is not allowlisted while suspended. Inactive fresh status plus a denied history remains an explicit error, with no automatic retry loop.
- Reasons are `SelectableText`, not HTML/Markdown or automatic links; staff wording is never translated/trimmed/paraphrased. Only draft interface labels/explanations are localized.

Real authorization is not inferred from mocked tests. The existing authenticated consequence verifier retains affected/unrelated/Creator/delegate/Resource-owner assertions and now adds 23 canonical apply/remove notices in one statement, yielding tied apply times across two bounded pages with unique IDs and exact ten-field/verbatim/null-content checks. It does not edit timestamps or relax chronology constraints. The suspension verifier retains active denial and adds general-history visibility only after canonical revocation, with removed suspension reasons/timestamps. Existing observed-lock/consequence/suspension gates are unchanged.

The freshly replayed task-local `pg_get_functiondef` and grants were inspected. Own history still has the ten-field descending tuple contract, `auth.uid()` identity match, profile-anchor and active-account guards. The separate four-field own-suspension status is the sole narrow exception; it does not allow general history while suspended. Both are fixed-search-path security-definer functions, with anonymous execution denied and authenticated execution allowed.
