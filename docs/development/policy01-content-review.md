## Manual deletion: remaining operator work

Leonardo monitors `developer.planets.community@gmail.com`. Requests use
`PLANETS — Richiesta eliminazione account`. The app prepares only the request
sentence and an optional email entered/reviewed by the user. It sends no token,
internal account ID, OTP, diagnostic, chat text or other person's data. Composer
opening never establishes Send, receipt or completion. App state is retained.

Before claiming operational deletion, validate a coordinated procedure on
synthetic data in a disposable environment: proportional requester verification;
all dependent application records and roles/projects/agreements; authentication
and session effects; personal profile/photo removal and placeholder projections;
Storage objects and derivatives; rights relating to message text; narrowly
justified retained evidence; providers/backups; and outcome confirmation.

The plan records previous staging findings: `public.profiles.id` and
`private.audit_events.actor_user_id` reference `auth.users` with `ON DELETE
RESTRICT`. These are **previous findings, not reverified live by POLICY01**.
Do not blindly delete an Auth row or disable integrity constraints. Inspect the
resolved Auth/Storage versions and current official documentation when designing
the separate procedure. No live account removal, destructive SQL, migration or
ad hoc retention change is authorised by this UI work.

The chosen placeholder and profile/photo removal remain intended behavior, not
implemented backend deletion. A request UI alone does not meet the complete
operational requirement. Actual moderation intervention and child-safety response
remain separate operational work. No Play submission, Data safety update, signing
change or closed-test clock is included.
