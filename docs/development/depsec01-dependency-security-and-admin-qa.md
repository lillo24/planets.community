### Reachability limits and genuine residual

Repository-wide import/script/config/docs search found no app JavaScript imports of these low-level libraries or explicit Undici specialized APIs. It did find **`@import "shadcn/tailwind.css"`**: shadcn is not CLI-only here and remains production-declared. Its registry/MCP CLI is a separate tooling input boundary.

Inspected Next production output: all **19 parsed NFT manifests** had no explicit `node_modules/<affected-family>/` entries, and named-library/source-map searches did not identify those package paths. However, server and SSR chunks **do contain Sentry configuration helper strings** such as `unstable_sentryWebpackPluginOptions`. The installed Sentry server barrel exports its deprecated withSentryConfig wrapper, whose graph imports config/webpack helpers and conditionally loads the webpack plugin. Thus package flags and missing trace paths are **not proof that inlined code is absent or unreachable**. No exploit was demonstrated; no blanket production-safe claim is made. Security updates were applied across the installed graph rather than relying on this uncertainty.

Residual `braces@3.0.3` remained latest/no-fix in the registry/advisory and the [upstream nested-pattern issue](https://github.com/micromatch/braces/issues/70). Its length/range limits are not a demonstrated nesting-depth remedy. Full residual entries: `braces`, `micromatch`, `fast-glob`, `@ts-morph/common`, `ts-morph`, `shadcn`, `@next/eslint-plugin-next`, `eslint-config-next`; production graph excludes the final two.

npm's suggested shadcn 1/Next 14 downgrades are incompatible with the accepted current stack and were not accepted. No compatible supported owner update removed R. Bounded operational mitigation: use reviewed repository/config/registry inputs for glob tooling, do not feed user-supplied patterns into it, and avoid exposing the development MCP CLI as a product server. These reduce the identified input opportunity; they are **not a patch or proof of exploit impossibility**. Residual acceptance or a separately scoped supported tooling replacement requires human review. No ongoing monitor was scheduled.

## Private-data verifier and fixture

The former `Synthetic PRIVATE` check did not cover the seeded `Synthetic private note N:` markers. This was a verifier weakness, **not evidence of an application leak**.

- The seed and verifier now share eight exact note markers plus actual private witness/counterstatement markers.
- Authorized moderator/admin HTML **and** Flight must first contain every selected marker. Anonymous, ordinary, and stale-role reads must omit all markers.
- Status, content type, private/no-store, rendered HTML not-found and Flight not-found digest are asserted together. Denied HTML is 404; applicable denied Flight is HTTP 200 with `NEXT_HTTP_ERROR_FALLBACK;404`. A digest cannot excuse leaked private text.
- **26 focused regression tests** include denial-shaped responses leaking each of the ten markers, missing authorized markers, and broken response contracts.
- Existing guarded loopback/backend scope, encoded Server Action transport, origin rejection, independent cookie jars and redacted nonzero failures remain.
- Stale-role existing-session HTML/Flight and encoded submit are tested after temporarily deactivating only the synthetic moderator's role; guarded local SQL confirms the submitted private note did not persist, and finally restores the role.
- The Resource fixture now uploads a real synthetic WebP to Storage and attaches it with the owner's canonical RPC. Metadata/signed URL alone is no longer used as cover-existence evidence.

A repeated-run fixture defect was found and fixed: 4,500 characters of Auth metadata appear in both user data and a refreshed JWT, producing **HTTP 431** at Node's normal header limit. Padding is now 2,000 characters and a JWT is rotated after the update. The later envelope-expiry request still requires a real Proxy refresh and multiple Set-Cookie chunks (observed **3 moderator / 3 admin** on final-source disabled/enabled monitoring reruns; an earlier rerun had 3 / 2). The server's header limit was **not** increased. Only safe status/cache/size/cookie-count metadata is logged before assertions; no response bodies, tokens, cookies, manifests or private notes are printed.
