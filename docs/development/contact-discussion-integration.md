`get_own_message_unread_summary_with_contacts_and_discussions(uuid)` reads D/M v3
and C's canonical discussion summary in one stable snapshot, subtracting their
shared legacy base once. Installed readers retain their own contracts. Project
folders are authorized visual aliases and contribute no extra conversation.
C ACK uses its text snapshot token; every other installed kind uses D/M ACK v3's
UUID boundary. The gateway then rereads the combined summary.

The unread controller listens to C's shared `discussionSignalsProvider`, alongside
the existing legacy/D/M gateway subscription. The resolved Realtime client 2.13.0
evicts a duplicate channel for the same topic, so it must not create a competing C
account channel. Signals clear counts before reauthorization; disconnection and
failure remain explicit. Account changes invalidate delayed reads and callbacks.

widgets, D representative cards and private member cards. Only Project chat IDs
enter C's bounded alias resolver. Notifications retains the contact-aware canonical
reader and independent C notices. Reports preserve both exact case evidence
loaders, own-history v4 and each typed target/context constraint and immutable
provenance trigger. No Group manager gains personal-contact access.

M's Request conversation. The additive
`list_group_discussion_invite_destinations(uuid,uuid,uuid,integer,timestamptz,uuid)`
requires both people to remain canonical people of the selected Group, excludes

and limit. Group managers need no ordinary membership/admission. Participants

General, archived/frozen

time. The strict parser rejects another context's Group/target or invalid ordering;
it fetches no profile, history, roster, link or read boundary. The selector grants
nothing. Submission uses C's existing invitation operation and canonical locks;
only explicit recipient acceptance creates admission. Both entry points scope

invalidation still clears protected attempts; Group hints/foreground clear
selector data before rereading. Invite eligibility never depends on M.canRequest.

## Exact populated histories

`npm run contact:discussions:upgrade:verify:local` is destructive only to the
explicitly selected disposable loopback stack. Set its container connection,
pipe, working-directory config and Mailpit URL first, with
`PLANETS_DISPOSABLE_QA=1` and `PLANETS_UPGRADE_QA_PROJECT` equal to that exact
isolated `project_id` (D uses `planets-community-d-qa`). Outside CI the verifier
rejects the default repository project and a missing/mismatched explicit project.
Never run concurrently with native, Auth or another
database check using that stack. No real or hosted data is supported.

The verifier resets and populates each exact immutable predecessor above, then
applies every missing interleaved migration with `--include-all`, twice. It checks
every original public/private table's columns and rows, warmed Block/worker/staff
function identities, ACLs and result contracts. Existing genuine lane verifiers
produce real OTP conversations and reports before the upgrade; the other lane's
verifiers run after it. Mixed checks require all six new report kinds, exact
one-of-fourteen typed targets, separate context bounds, rejected mixed targets
and cross-family contexts, submission-key conflicts, own report labels and
combined unread/auth parity. A separate sorted fresh replay remains required.

To select an exact predecessor, the verifier temporarily moves only the other
migration files into a newly created OS-temporary directory. It validates both
absolute parent paths, never rewrites SQL or repairs migration history, and
restores the files in `finally` before fixtures or upgrades. Its small
`restore.json` journal records the exact checkout, source and filenames. If the
process is forcibly terminated during reset, restore those original files from
that journal into its recorded migration directory before running another
command. Do not delete a journal's directory while any recorded SQL file remains
there. Completed journals contain no credentials and are retained for traceability.

Full classified CI runs both populated orders before its ordinary clean reset,
lint, advisors, SQL/Auth checks and combined type regeneration. The Database
timeout is 40 minutes because both actual histories add serialized local resets
and genuine fixtures; area selection and trigger frequency are unchanged.
Final CI and native results belong to the cumulative PR; no native success is
inferred from compilation or from an app-pass/host-failure result.

The separate opt-in [Android workflow](../../.github/workflows/contact-native.yml)
provides an authorized alternative when the shared Windows host lacks memory. It
uses a standard ephemeral GitHub-hosted Linux runner, a runner-local database,
genuine synthetic OTP sessions and a headless owned Android VM. It never targets a
hosted database or store. Label triggers, exact-head freshness, cost and the
screenshots-only artifact boundary are documented beside the workflow. Driver
completion and subsequent visual inspection remain mandatory; adding the workflow
is not itself a passing Android test.
